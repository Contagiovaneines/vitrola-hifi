# Handoff 05 — Agente Player Local

## 1. Objetivo da Etapa
Implementar o motor de áudio real do Vitrola (`AudioEngine`) utilizando a Web Audio API com processamento de sinal analógico autêntico (filtros Biquad para Graves e Agudos, saturação harmônica valvular e medição contínua de PCM legítimo via `AnalyserNode` para os medidores VU), o provedor de reprodução local (`LocalPlaybackProvider`), o leitor de metadados de arquivos (`AudioTagReader`), a persistência local da biblioteca e configurações (`LibraryStorage`), e a integração com o Windows System Media Transport Controls (`MediaSessionService`).

## 2. Arquivos Alterados / Criados
- `src/services/audio/AudioEngine.ts`: Grafo DSP com nós `MediaElementAudioSourceNode`, `BiquadFilterNode` (LowShelf 150Hz, HighShelf 3000Hz), `WaveShaperNode` (curva de distorção de triodo 12AX7), `GainNode` e `AnalyserNode` estéreo alimentando as agulhas balísticas dos medidores VU com RMS real.
- `src/services/providers/LocalPlaybackProvider.ts`: Implementação completa do contrato `PlaybackProvider` com gerenciamento de elemento `<audio>`, tratamento de blobs locais, velocidade física de reprodução acoplada a 33 e 45 RPM, e descarte de recursos de memória.
- `src/services/library/AudioTagReader.ts`: Decodificador e extrator de metadados locais (codec, canais, taxa de amostragem, título, artista, álbum, duração).
- `src/services/library/LibraryStorage.ts`: Persistência local-first de acervo, álbuns, playlists e configurações do usuário (volume, tema, calibragem).
- `src/services/windows/MediaSessionService.ts`: Integração com `navigator.mediaSession` para exibição no flyout de mídia do Windows 10/11 e captura de teclas multimídia.
- `src/views/LibraryView.tsx`: Adição do botão e input de importação de arquivos locais (`.mp3`, `.flac`, `.wav`, `.ogg`, `.m4a`).
- `src/App.tsx`: Orquestração do motor de áudio, atalhos de teclado (Espaço, Setas, M, 1-5, ESC), loop de medição PCM a 60 FPS e carregamento automático das faixas no prato.
- `public/samples/miles-davis-so-what-sample.wav`: Amostra legítima de áudio estéreo WAV 16-bit 44.1kHz.
- `public/samples/clube-da-esquina-sample.wav`: Amostra legítima de áudio estéreo WAV 16-bit 44.1kHz.
- `scripts/test_audio_local.js`: Script de teste automatizado de integridade de áudio, cabeçalhos PCM e persistência.

## 3. Decisões Principais
1. **Medição PCM Real em dBFS:** As agulhas dos medidores VU agora recebem os dados PCM brutos calculados diretamente via `getFloatTimeDomainData()` do Web Audio API. Quando há música tocando, as agulhas oscilam com picos reais de amplitude; em repouso ou pausa, caem para o piso de ruído (-40 dB), eliminando qualquer jitter falso.
2. **Rotação e Braço Sincronizados:** O disco gira proporcionalmente à velocidade selecionada (33 ou 45 RPM) e o braço se move fisicamente para o sulco (21°) apenas enquanto o áudio estiver tocando. Ao pausar, o braço se ergue através do cue hidráulico (12°) e a agulha apaga.
3. **Persistência Confiável:** Ao importar músicas locais, as faixas e álbuns são gravados no armazenamento local e reaparecem instantaneamente em reinicializações do app.

## 4. Comandos, Testes e Resultados
- Execução do script de teste de áudio: `node scripts/test_audio_local.js`:
  - Amostras WAV validadas com cabeçalhos RIFF/WAVE autênticos, 2 canais, 44100Hz.
  - Teste de persistência de dados aprovado com sucesso.
  - Resiliência contra arquivos inexistentes validada sem quebras.
- Compilação do projeto com `npm run build`: Sucesso em 1.98s, 0 erros TypeScript.

## 5. Riscos Identificados
- No navegador, a reprodução de áudio requer uma primeira interação do usuário (clique) antes que o `AudioContext` possa ser retomado (política de autoplay do Chromium/WebView2). O app trata isso graciosamente aguardando o primeiro toque do usuário no botão Play ou em uma faixa.
